# Product and current behavior

This document describes existing VK Audiopad behavior for contributors and AI agents. It is based on code; live observations are identified separately. Planned behavior changes must be accepted and verified in their own task rather than inferred from expectations of a typical music player.

## Purpose and interface

Users open a compact player, find music in their VK catalog or search, and listen independently of the popup. The same index.html can run in an extension tab; settings link to the tab version. VK login must happen in the browser profile where the extension is installed. Sessions from another browser or profile are not automatically shared.

Fast opening, first usable music and responsive scrolling are priority product requirements. Changes that add a request or awaited dependency before usable content, gate it on optional enrichment, or replace an available fast source with a slower one require comparable production measurements, a written justification and explicit user agreement before implementation. Review first usable content, request dependencies and warm returns as part of frontend changes. The [profiling workflow](../ai/ui-debugging.md#startup-performance-review) defines the comparison and CI safeguards.

The player column fills the available width between 780 and 1216 px. In wider browser tabs it stays centered with equal space on both sides; the popup keeps its 780 px minimum width. The player header shares the column's width and alignment.

Catalog blocks and their ordering are personalized. A collection missing from another account is not sufficient evidence of a parser defect. UI is driven by returned data, not the block list of a particular profile.

Home, My music, Explore, Radio and Current playlist mount on their first visit within an open UI. Visited pages retain their local state, including an unsaved queue editor draft, across navigation. Closing the popup or changing accounts recreates that state. Catalog and library-playlist queries reuse successful results for 30 seconds. Returning after expiry refreshes the data while keeping cached content visible. Mutation invalidation takes effect immediately, including during that freshness window. Each new popup has a fresh query cache.

Listening cards with missing track previews request them when the card approaches the viewport. Cards with embedded previews need no additional read. Preview skeletons reserve the populated card height.

Horizontal collections use the shared HorizontalScroll wrapper over VKUI. Available arrow buttons are exposed to assistive technology and keyboard focus. Entering a rail with keyboard focus reveals its arrows without requiring pointer hover. When a focused arrow disappears at a boundary, focus moves to the named scroll region with preventScroll. Ordinary content updates retain arrow focus. The wrapper owns the root/arrow focus refs and accessibility slots.

Track-row actions run from play-next through track Mix and similar tracks to playlist saving and the library add/delete action at the right edge. Hidden actions give their space back to the title. Pointer hover or visible keyboard focus reveals aligned controls and temporarily replaces the duration, retaining row height. The 64 px player places Previous, Play/Pause, Next and shuffle/repeat before the cover. Its center stacks title and artist beside library/playlist actions, recommendations/lyrics and time, with a progress slider spanning the full center underneath. Volume and broadcast sit at the right edge. Transport hover uses the existing neutral primary/secondary icon colors in both themes. Spacing separates action groups. The decorative cover has no button role. Track titles truncate according to available width, and transport/position/volume controls have accessible names. Empty metadata reserves the same two-line space.

Track rows keep their titles, artists and playback controls mounted throughout loaded lists. Normal rows isolate layout and style calculation with CSS containment. Action buttons are prepared after a row remains within 300 px of the viewport for 150 ms. Pointer entry, touch and keyboard focus prepare them immediately. Once prepared, actions retain local state until their row unmounts. Restore controls and the draggable queue editor prepare eagerly. Browsers without IntersectionObserver also prepare eagerly.

Player icons are centered inside their targets, with native SVG padding removed from transport controls. Their glyph boxes have equal 12 px intervals across transport/modes and track actions. Compact players use 20 px action glyphs, wider players use 24 px. The broadcast glyph receives a 1.17 optical scale inside its existing target. Elapsed/remaining time uses 11 px tabular numerals beside the artist row. The volume icon toggles mute, updates its accessible action name and icon, and restores the remembered positive level even after reopening the popup. Moving the slider above zero also restores sound. Missing/invalid remembered volume falls back to 50 percent. Muting cancels an uncommitted slider write. Mute changes volume through the existing setting observer while playback continues.

## Accessibility

The document declares Russian. The player and main content have labelled landmarks and keyboard-only skip links. Retained pages are hidden and inert while inactive. Navigation tabs have unique IDs and existing panel targets, and dialog actions use named buttons. Arrow keys move tab focus, and Enter/Space activates a tab. Route changes transfer focus to the selected visible tab or detail heading while preserving an active search input. The global playback shortcut leaves native controls, navigation tabs and links to their own keyboard behavior.

Track playback, artist navigation and row actions are independent controls. Album/recommendation navigation and overlay actions are siblings. Track metadata and durations use text semantics, and decorative covers have empty alternative text. Loading placeholders are hidden/inert under a loading status. Track changes have a polite announcement, while position ticks stay outside live regions. Shuffle and broadcast expose their pressed state, and repeat describes the current mode. Seek uses a native seconds range with spoken elapsed/total time and native arrow, Home/End and Page Up/Down behavior. Unknown-duration streams disable seeking. Volume exposes percentages. Queue editing offers named up/down buttons in addition to dragging, and paginated lists have a keyboard-revealed continuation button alongside viewport loading.

Normal pointer appearance, colors and spacing remain unchanged by the accessibility work. Focus indicators and skip/continuation helpers appear during keyboard use. The system's `prefers-contrast: more` increases secondary text contrast, and forced-color focus indicators use system colors. Reduced-motion preferences suppress decorative transitions and the Mix animation loop. Hidden Home pages stop that loop. The default VKUI palette retains known secondary-text contrast limitations. Automated checks and keyboard evidence are recorded in [testing](../ai/testing.md#accessibility-and-collage-checks-november-8-2026). VoiceOver/NVDA speech verification remains open.

Progress and volume use thin VKUI tracks with transparent thumbs. Hover previews the time or percentage at the pointer position, clamped to the available range. Preview state stays local. Native range inputs retain their labels, value text and keyboard operation. Keyboard focus outlines the track and shows its current value. Escape dismisses the hint until another hover/focus interaction. Pointer-only hints end on departure. An unavailable duration disables seeking.

## Playback scenarios

- Choosing a track sends its ID and playlist context to the SW. The SW resolves a current media URL, prepares the queue and passes the source to the audio context. Selection/metadata may appear before actual playing; verify played, progress and media events.
- Play/pause toggles the SW-owned requested state, including during loading. Two quick toggles end paused even before the first playing event; a third resumes the cancelled selection. The header/active-album/Mix action can show pause before media starts. Resume of an already launched source preserves its position; missing media or a terminal failure causes a reload. Repeated selection of a track whose metadata has not committed still selects it rather than toggling. Closing the popup does not send pause.
- In both the toolbar popup and an extension tab, Space toggles playback through the same SW command and prevents page scrolling immediately after opening, without a preliminary click or asynchronous tab detection. Focused navigation tabs and links keep their native keyboard behavior. Holding Space sends only one toggle. Modified/composing/already-handled keystrokes, editable fields, controls with their own Space action and open dialogs keep their ordinary keyboard behavior. The key is recognized even without a physical key code; existing browser/global shortcuts remain available.
- Generated recommendation cards on Home (for example, «Для вас», «Открытия», «Новинки») darken their full cover on hover and reveal a centered play/pause icon. It uses the other albums' glyph at 48 px and changes from white to the theme's secondary text color when hovered. Its hover/press background layers are disabled: only the glyph changes color, without a circular backdrop or ripple. The button has an accessible name without a hover/focus tooltip. Keyboard focus also reveals the control with a rectangular focus outline; moving the pointer away after a mouse click hides it again. It loads the playlist and starts from the first track without opening the playlist page; clicking the rest of the card still opens it. An active card pauses/resumes through shared playback intent. Loading retains focus and blocks duplicate requests; empty/failed loads show safe feedback and allow explicit retry. Choosing another card cancels the previous card read. Leaving the UI/account cancels pending card loading and late results cannot start playback.
- Chrome may reclaim a paused offscreen document after more than 5 minutes without media/control activity. A later play reloads that selection; it does not preserve a destroyed Audio element or its position. Concurrent play wins over unissued cleanup; an issued close finishes before a new source is sent. Firefox does not use idle document cleanup.
- Next/previous moves through the current queue, or the latest pending selection while loading. Full queue hydration is asynchronous: the number of visible cards does not determine the number of available IDs.
- Play-next inserts after the active track in the full queue and the loaded list without wrapping to the front. Queue edits do not mutate the VK library or stop a removed playing source. Shuffle preserves selection and can restore canonical order; editing moves during shuffle changes restore order, while removal applies to both orders. External queue changes cancel an open editor draft. See [queue ownership](../decisions/0004-queue-mutations.md).
- Ordinary playlists, radio and VK Mix differ through isRadio/isVkMix. Mix can request another recommendation from VK; do not treat it as an ordinary finite array.
- Request failures, missing URLs, launch failures and media errors retry the same track up to three attempts, then advance. Five consecutive failed tracks (including the initial selection), a shorter exhausted queue or the 15-attempt Mix safety limit stop playback. Actual playing resets consecutive failures. A compact, persistent error card offers “Попробовать снова” and local dismissal without shifting the header or page content. The exact cancellation/attempt contract belongs to [the ADR](../decisions/0001-playback-operations.md), not individual UI components.

**End-of-queue behavior needs care.** Currently onEnded replays the current track for REPEAT_ONE and otherwise calls next; getNewIndex wraps an ordinary queue from its end to its beginning. Do not assume RepeatMode.NONE stops playback at the boundary. This is derived from [on-audio-ended](../../packages/service-worker/src/actions/on-audio-ended.ts), [next](../../packages/service-worker/src/actions/next.ts) and [getNewIndex](../../packages/service-worker/src/utils.ts); natural end was not covered by the live smoke. Desired end-of-queue policy remains a [product decision](../ai/development-roadmap.md#product-decisions-before-behavior-changes).

## Equalizer

Settings uses always-visible “Звук”, “Внешний вид” and “Управление” tabs in a fixed, viewport-capped modal frame. Sound contains one equalizer toggle row showing the saved preset/custom setting. Enabling it reveals a preset selector, ten vertical frequency faders and a separate Preamp (-12 to +12 dB), a shared scale at 6 dB intervals and reset; disabling it removes the detailed controls while retaining the curve. The player toolbar has no separate equalizer icon. Appearance and Controls remain reachable from the pinned tabs while Sound is open; switching sections and toggling EQ keep the same frame size. Frequency/value labels stay visible; arrows, Page Up/Down and Home/End adjust the focused band. The [design study](equalizer-design.md) records references and choices.

Equalizer settings survive popup closure, extension updates and account changes. Turning it off retains the selected curve. Twelve built-in curves cover tone adjustments and music/speech styles; manual bands and Preamp can be saved as multiple named personal presets, recalled, updated with Save Changes, copied with Save As, renamed and deleted with confirmation. Editing retains the selected personal preset and its delete action; only explicit save overwrites its saved curve. “Ручная настройка” describes the current unsaved-as-a-name curve, while Save As adds a named copy. Existing “Мой пресет” data migrates to the collection, which survives settings-preserving cleanup. Reset always selects “Ровный звук” and clears active bands and Preamp, preserving the named collection and allowing immediate recall of the previous personal preset, including a neutral one. Boost compensation defaults off (an existing explicit choice is preserved) and estimates the combined filter response rather than summing all positive gains. Its explanation is in a tooltip; Preamp always remains a separate manual adjustment. Positive Preamp can distort. Waiting/active boilerplate, the visible preset heading and redundant band-count subtitle are hidden. Preparation/unavailable state appears in a compact, separate current-track strip above the controls. Appearance retains its palette icon and uses a compact labeled theme field instead of spreading its label and control across the modal. Legacy five-band built-ins map to ten-band versions; other saved curves are approximately interpolated over frequency. Theme, shortcut guidance, opening the player in another tab and Chrome shortcut-creation guidance remain available in their own groups.

HLS applies changes directly. For ordinary media with EQ enabled, the player prepares a local copy and its processing graph before starting once, avoiding a source replacement during the first seconds. This can add startup latency. First enabling EQ during an already-native track can still briefly rebuffer while preserving position. If the CDN denies the fetch, the file exceeds 32 MiB or preparation exceeds 15 seconds, native playback starts without processing and settings show that the equalizer is unavailable for the track. Preset/band changes retain this unavailable state without retrying the denied source; grant/re-enable or a new source can retry. The Mix CDN uses optional https://*.okcdn.ru/* access. Without the grant, processing skips the fetch entirely on every track, preserving native playback without predictable CORS errors. After a grant the current track is processed from the same position; genuine CDN/network failures still fall back to native playback. A lock/warning card makes missing Mix access distinct from ordinary settings. Enabling EQ first explains why it is needed; only “Разрешить” opens the browser prompt. Refusal leaves ordinary EQ/music working, shows that Mix EQ is unavailable and offers “Выдать доступ” to retry. Access is not requested at install/startup, and a remembered refusal suppresses repeated automatic explanations. See [ADR 0010](../decisions/0010-equalizer.md) for ownership and limits.
Updates crossing 3.3.10 from an older version show a one-time Settings hint about EQ, even when skipping that release. Later updates from 3.3.10 or newer do not repeat it. Missing okcdn access during actual playback with enabled/unavailable EQ shows a separate Settings hint directing the user to Sound permissions. Both appear after a 1.5-second delay, can be dismissed and close automatically after five visible seconds. Opening Settings or granting access during the delay cancels an obsolete hint.

## Track lyrics

The player shows “Показать текст” with VK's Icon24TextTtOutline only when the active track advertises lyrics. Legacy tuples retain HAS_LYRICS; token tracks map has_lyrics into the same flag. Missing availability does not trigger a speculative lyrics request. Existing stored token tracks are not backfilled; newly resolved tracks use the updated conversion.

Opening the VKUI reading dialog loads audio.getLyrics through the common token client. Both lyrics.text string arrays and lyrics.timestamps objects with a string line or an explicit interlude=true marker are supported; plain text takes precedence when both are supplied. Interludes become blank lines. Returned line order, repeated lines and stanza breaks are preserved. The dialog shows track/artist metadata and selectable plain text, without a second player or synchronized highlighting. Loading, safe failure with explicit retry, and unavailable-text states are distinct. Closing restores focus and cancels an unfinished read; changing tracks or accounts closes the dialog. Lyrics cache entries belong to the current UI/account and track ID, contain no credentials in their keys, and are not persisted. Reading/closing lyrics sends no playback commands and does not write playback/queue state; token refresh retains the shared client's existing lifetime.

Closing the lyrics reader restores focus without reopening the button's tooltip. A later hover or deliberate keyboard focus shows the tooltip normally; it remains hidden while the reader is open.

## Loading more list data

Only the visible page may automatically load the next page. Pagination reads fail visibly even when offline, instead of being suspended for automatic reconnect replay. An error stops automatic pagination and offers “Повторить” while keeping loaded rows. Within a mounted list scope, a cursor is attempted automatically once; an unchanged or cyclic cursor stops with “Список не продолжился” and explicit retry. Reopening/remounting a list starts a new local attempt history. Changing list/account scope separates cursor histories. Personal query caches are separated by stored account; playlist owner/context separates equal IDs. Page results merge immutably by ID and an obsolete cursor cannot replace a newer page. [ADR 0007](../decisions/0007-query-identity-and-pagination.md) states the limits: shared tokens, external mutations, all-catalog invalidation and some token-resolution work are outside this cache boundary.

## Library deletion and restoration

The music website is the behavioral reference; [the parity matrix](vk-parity.md) distinguishes observed functions from unchecked ones. After confirmed deletion of an owned track, retain a muted row and enabled restore plus. Successful restoration keeps the queue entry. Navigation expires restoration and removes pending IDs from the local queue; closing/reloading the popup ends restoration but leaves the queue unchanged. VK deletion is immediate and independent of that local queue lifetime. [ADR 0006](../decisions/0006-library-delete-restore.md) defines late replies, failures and direct deletion without restoration.

System appearance is resolved synchronously through matchMedia before the first ConfigProvider render and follows later system changes. Explicit light/dark preferences retain their selected appearance. This keeps the early VK Mix button in its final startup palette.

The HTML entry contains a fixed-size startup skeleton before the JavaScript bundle runs. Account hydration retains that skeleton until the account query tree can mount. Toolbar action popups keep a 780×600 document and use VKUI’s contained AppRoot scroll controller. Modal scroll locking stays on that container, preserving Firefox’s intrinsic popup height. The contained viewport retains its scrollTop while locked, so VKUI’s saved negative top offset is neutralized visually to keep the background stationary during playlist creation and editing. Full extension tabs use global document scrolling. Navigation resets the active scroll controller, and closing a modal restores its previous position.

Playlist and collection pages omit a track-group heading only when it exactly matches the visible navigation title. Distinct headings remain visible.

## Home discovery tiles

Playlist artwork uses valid `thumbs` in server order before the standalone `photo`. VK can populate `photo` with the first collage tile. One image fills the cover, two split it vertically, three use a full-height left tile and two right tiles, and four fill two columns from top to bottom. VKUI GridAvatar supplies the arrangement with zero internal image offset.

My music and Explore render supported token-catalog groups with matching legacy track data. Token-first completion preserves their returned order, with My music using a stable library slot after the leading music group. My music pins its first fast group. Explore keeps the original catalog order regardless of response order. Each page shows independently ready data while its remaining sources load. Optional enrichment preserves already mounted controls and layout. The account query tree mounts after userId storage hydration.

Home, My music and Explore start their legacy HTML section read and token catalog together. The first nonempty source supplies usable content. All initial catalog and library caches use the account-scoped 30-second freshness window. Only active pages initiate these reads.

Home and My music pin the first useful legacy block when that response arrives first. Matching block IDs or nonempty normalized titles remove the duplicate token block of the same type. The pinned block retains its legacy track metadata and receives the matching token show-all destination. Token-first completion preserves token order, with later legacy data enriching the existing groups.

Explore preserves the original catalog order with either response order. When legacy data arrives first, its first titled block appears at its original position, with loading slots reserved for preceding unfinished groups. The banner slot uses the same grid, cover and label geometry as the populated banner rail. “Сегодня в плеере” remains below the promotional group. Once token data arrives, its complete order is authoritative. A matching fast block retains its DOM key, focus and layout at that position. Title matching normalizes whitespace, including nonbreaking spaces.

A loader remains below available content while the token request is pending, including when the user scrolls early. A token failure keeps legacy content available with retry feedback below it. Explicit retry also retries a failed legacy source.

Home and Explore use one token-catalog pagination owner and one continuation indicator. Other unmatched legacy groups become available when the token catalog fails. Continuation pages merge groups by block ID. Matching IDs or titles supply legacy track metadata. Catalog continuations load when their sentinel enters the viewport. Each cursor receives one automatic attempt, repeated cursors stop pagination, and failures retain existing content with an explicit retry. “Ещё подборки” also supports manual continuation. The continuation spinner is centered inside a card with the same boundaries as the surrounding groups.

Genres and moods/activities use two-row horizontal rails of 198×48 px tiles. Current VK responses provide play_vk_mix actions. Activating one starts its exact mix_id and optional mix_options through the existing SW playback owner. Further activation toggles that Mix. The main VK Mix action starts or toggles the common Mix with the remembered selection. “Настроить” opens the server-supplied mood, recognition and language groups, with one optional value per group. Draft changes and Reset stay local until “Применить”, which starts a fresh Mix immediately; closing cancels the draft. Genre/activity tiles update the main selection, and their additional context survives applying mood/language settings. The main reset clears every filter and starts the unrestricted common Mix. Choices are remembered per account in vkMixPreferences independently of the current playback queue, so ordinary playlist playback and reopening the popup do not discard them. Settings reads have skeleton, cancellation and explicit retry states. The dialog uses a VKUI portal outside the transformed hero. Older supported catalog links retain their internal navigation and separate collection-play action. Category backgrounds brighten on hover. The configured summary and reset icon share one adjoining control. Titles, images and destinations come from VK.

“Слушайте друг друга” retains its server cover, optional author/avatar and three track previews. Current recommended_playlists packages provide the cover, embedded audios and fractional match percentage. Header open_section actions supply “Показать все”, which opens the album collection using ordinary playlist photos or collages. Recommendation gradients remain confined to the listening rail. Opening a playlist loads its full track page. Missing previews or artwork retain explicit loading, fallback and retry states.

Artist Mix cards preserve separate background and foreground images, with 198×240 px backgrounds and 137 px round portraits. Artist Mix playback preserves the separate entity_id alongside mix_id=artist_mix. Play appears on hover or keyboard focus, and the active pause remains visible. Artist pages preserve the token catalog’s “Вам могут понравиться” group with compact 48 px portraits and internal artist navigation. The same header-action handling supplies show-all destinations for other groups. Algorithmic cards use 198×240 px covers and left-aligned text, and ordinary album covers measure 144 px. Horizontal rails preserve their own scroll areas. Promotional banners retain their image, title and text. Internal click_action links can open album, artist and curator destinations. Curator pages resolve through catalog.getAudioCurator.

“Микс по треку” appears on available music rows and beside the active track in the player. Each activation starts a fresh track_mix with entity_id equal to that source recording ID. Subsequent recommendations preserve it through the existing SW Mix path. Radio streams and unavailable recordings omit this action.

## Friends and radio

Person cells use a neutral VKUI user fallback if their image is missing or fails. “Музыка друзей” renders 48 px server-supplied round avatars with left-aligned names and audio counts beside them in 225 px cells in My music and in Explore's continuation. “Показать все” opens the full friend grid. Selecting a friend or curator resolves the referenced user's or community's audio catalog. Visibility and access remain subject to VK's response.

“Радио” is a separate navigation tab backed by the radiostations catalog route. Station cards preserve server names, logos and background colors. Activating a card plays its direct stream through the existing isRadio path, including pause/resume and next/previous. ## Server playlists

My music starts audio.getPlaylists independently of both catalog responses. One stable library slot follows the leading music group, with a track skeleton reserving that group while it loads. The library can become usable before either catalog completes. Later catalog metadata updates its show-all link without remounting the library or duplicating a legacy playlist group. Library failure has its own retry and preserves loaded music.

My music has one “Плейлисты” block containing owned playlists, followed collections and release albums in server order. Its first tile creates a playlist. Covers, up to four-image collages and titles come from audio.getPlaylists. Tiles and full grids show original-author or release-artist credits with 16 px avatars where supplied. Followed copies resolve their original owner. Hover/focus reveals track and listening counts with their respective icons, including Explore’s “Оставаться в тренде” albums. Cover action glyphs change color on hover/focus. Direct play controls, removal of followed collections and “Показать все” complement opening a playlist. Token following retains the returned library-copy identity. Removal targets that owned copy, resolving it from the complete account library when necessary, within one bounded session. Only owned editable playlists expose editing. Their cover places an edit icon beside Play with the generic “Редактировать плейлист” tooltip. Playlist titles occupy one ellipsized line. The playlist track page places the edit icon at the end of its navigation path. Album cells use VKUI’s numeric width with 20 px cover separation, including the first two cells. Full album grids also have explicit row and column spacing. The track-to-playlist picker continues to offer owned editable destinations.

Playlist-dialog actions hide their tooltip on activation and suppress the immediate focus-return hint. Closing or completing a dialog restores the trigger focus. Moving the mouse away restores a track row's duration and hides its actions, while keyboard-visible focus retains the controls. Subsequent hover and a genuine new focus can show the hint again.

Creation and editing support title, description, search/recommendation visibility, track selection from the paginated music library, removal and reordering. Editing loads every playlist track before enabling the form. Draft changes remain local until Save. audio.editPlaylist sends the complete ordered audio_ids snapshot, including access keys. VK prepends initial audio_ids during audio.createPlaylist, so creation reverses the transmitted list to preserve the visible draft order. Adding an individual track uses audio.addToPlaylist. Deleting an owned playlist requires an explicit confirmation in its editor.

JPEG/PNG cover uploads support files up to 5 MiB with dimensions from 300 to 7000 px. A local preview accompanies the staged upload. Upload and attachment use the website's observed 5.255 cover protocol through the shared session owner. Staged credentials stay in UI memory, bound to the initiating user and epoch. Cover replacement/removal commits after playlist metadata. If that second stage fails, the UI reports the saved playlist, locks its committed draft and retries only the cover stage. Confirmed photo-save output is reused during attachment retry. Closing before Save leaves playlist metadata unchanged. Closing after dispatch cannot undo an issued server mutation.

The current queue's “Сохранить как плейлист” captures audiosIds, including unloaded IDs and access keys, in playback order. The action snapshots available track metadata and resolves missing names through batched audio.getById reads before opening the editor. Server omissions retain an explicit unavailable-recording label. This finite snapshot can include Mix history. Later queue edits do not alter the submitted selection. A queue still being hydrated should finish loading before saving if all source tracks are wanted. This operation creates a server playlist and preserves playback storage.

Only validated mutation responses produce success feedback. Ambiguous failures retain safe feedback and require an explicit user decision before retrying. The token client's single explicit authorization retry remains bounded. Account/epoch retirement follows [ADR 0009](../decisions/0009-session-owner.md). Successful mutations invalidate the initiating account’s playlist, My music, show-all album and token-catalog queries even if the dialog closed while the request was pending. A closed dialog emits no completion notification. Reopening an invalidated show-all album page refetches its contents. Other windows retain independent caches. No playlist database or new persistent storage keys are introduced.

[The parity follow-up](../ai/testing.md#catalog-and-playlist-parity-follow-up-november-7-2026) records controlled checks, authenticated round trips and remaining browser evidence.

## Persistence and external changes

Reopening UI restores observed state from storage. Theme uses localStorage; playback, queue, selected tab and most controls use chrome.storage.local; the query cache belongs to the open UI. See [state/messages](../ai/state-and-messages.md) for the full map and recovery limitations.

Installing over the same extension path preserves settings, while the UPDATE handler removes runtime data. Account changes also clear associated data. This is current behavior, not a migration system that preserves queues; T11 covers its evolution.

Library add/delete, album follow and status broadcast actions can change external data or visible user status. Include them in live checks when they are part of the task; ordinary catalog/playback smoke does not require library mutations. Playback itself sends listening notifications to VK and can affect history and recommendations.

## Interface recovery

React render/lifecycle failures inside the application (including providers) show “Не удалось открыть плеер” with a focused “Перезагрузить интерфейс” button. The fallback uses native HTML/CSS so it does not depend on the failed VKUI/query providers. Activation reloads only the UI document; it does not clear storage, reload the extension or command playback. Background playback has its own lifetime. UI destruction ends transient restoration/edit windows under their existing contracts.

The handled error is not displayed or logged with its original message/stack; the root reports a fixed safe diagnostic. This boundary does not catch errors before React mounts, event-handler exceptions or detached Promise failures. Those need explicit handling at their owning action. Reload can encounter a persistent defect again; there is no automatic retry loop or claim that reloading repairs data.

## Current quality boundaries

Minimum browser versions are declared in [the manifest generator](../../public/manifest.js); declarations are not a verified browser matrix. Chrome and Firefox share source but have materially different runtimes.
