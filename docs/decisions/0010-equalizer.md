# ADR 0010: background equalizer and cross-origin audio

Status: accepted for the ten-band implementation with manual Preamp. Browser evidence and limits belong to [testing](../ai/testing.md).

## Ownership and settings

The settings modal owns a Sound tab with a toggle and saved-curve summary. Detailed controls mount only while enabled. [The design study](../product/equalizer-design.md) records references and UI choices. `equalizer` is one flat Chrome storage key containing `{ enabled, gains, preamp, autoGain, userPresets, presetId, mixAccessDenied }`. Gains are ten integer decibel values at 32, 64, 125, 250, 500, 1000, 2000, 4000, 8000 and 16000 Hz. Manual Preamp is -12 to +12 dB and defaults to 0; autoGain (boost compensation) defaults to false; an explicit stored true remains enabled. Missing/malformed active gains become neutral values and are independently rounded/clamped. UI writes replace the complete normalized object.

User presets contain stable IDs, names, ten gains and Preamp. The UI supports Save Changes, Save As, recall, rename and explicit confirmed deletion, rejecting blank/duplicate names. Changing bands or Preamp retains the selected personal preset identity: audio changes immediately, while its saved curve changes only after Save Changes. Save As instead creates an independent named copy. Delete remains available while that preset has unsaved edits and retains the current sound. Names and IDs are bounded to 64 characters; malformed saved curves and duplicate IDs are dropped on normalization. The old savedGains/savedPreamp pair migrates to one named entry, “Мой пресет”, without overwriting existing entries. presetId retains the selected preset during editing and distinguishes named presets with identical sound. Twelve built-in curves remain immutable starting points; “Ручная настройка” describes a current curve without a matching named preset. Reset always selects “Ровный звук”, clears the personal selection and pending naming/deletion forms, and resets active bands/Preamp without modifying the collection. An explicitly selected personal preset remains identifiable even if neutral; after reset, matching built-in curves take precedence over implicit personal matches, so the personal preset can be recalled immediately. mixAccessDenied remembers an explicit deferral/refusal without disabling EQ; it defaults to false. The key is in ApplicationSettings, so the existing UPDATE/account cleanup preserves the entire collection; this is tested through the actual clearStorage helper and live same-path update. Reads do not write migration results until the next user edit.

[Offscreen equalizer](../../packages/offscreen/src/equalizer.ts) owns application to sound, independently of the popup and SW lifetime. Chrome offscreen documents only have the runtime extension API, so SW storage listeners forward CHANGE_EQUALIZER over the existing ready transport. They do not create an absent Chrome audio document for a settings change. PLAY_TRACK includes normalized settings read immediately before delivery, including changes during document creation; missing settings retain neutral compatibility. The SW checks the actual optional Mix host grant immediately before delivery and forwards equalizerMixAccess on PLAY_TRACK and CHANGE_EQUALIZER; a missing flag or failed permission lookup means no access. Async message preparation rechecks command ownership before delivery, and newer settings supersede delayed older settings. This is DSP configuration, not a playback command. Offscreen reports EQUALIZER_STATUS with playbackId; SW writes the transient `equalizerStatus` key only for the matching stored source. Settings cleanup removes it. Firefox uses the same messages through its CustomEvent bridge.

A single AudioContext contains a gain stage followed by a low shelf, eight peaking filters and a high shelf (Q=1). Initial values are applied immediately, cancelling previous parameter ramps before first playback; later live changes use a 20 ms target constant. With autoGain enabled, compensation estimates the combined filter response using matching RBJ coefficients at the context sample rate and a logarithmic frequency grid, with 0.2 dB margin rounded upward to 0.1 dB. Manual Preamp is added separately, so changing it always changes the level. This replaces the excessively conservative sum of all positive band gains: at 48 kHz Bass has a native Web Audio peak near +6.886 dB and compensation of 7.1 dB, rather than 17 dB.

Compensation is optional static gain, not track loudness normalization or a dynamic limiter; positive manual Preamp can still distort. The checkbox has a concise tooltip instead of a persistent calculated-level paragraph. Disable keeps an existing graph neutral at unity gain. Resume requests also resume the context. Replacing/destroying a source disconnects its node, aborts pending work, removes metadata callbacks and revokes its object URL.

## Five-band compatibility

Normalization recognizes legacy five-value curves without a storage-version write. Known built-ins map to their new ten-band counterparts. Other five-band curves are linearly interpolated in decibels over log frequency, extending the endpoint values below 60 Hz and above 14 kHz, then rounded/clamped. Saved personal curves follow the same conversion and default to 0 dB Preamp. This preserves the intent approximately, not the exact old filter response or loudness. Reads do not overwrite storage; the next user edit writes the normalized settings. Re-normalizing that ten-band result is idempotent. Reset clears active bands and manual Preamp, preserving user presets and compensation preference.

## Media safety

Audio.crossOrigin stays unset as required by ADR 0001. Connecting a cross-origin, non-CORS native Audio directly to a MediaElementAudioSourceNode can silence it. HLS already uses a local MediaSource through hls.js and can enter the graph immediately. For direct okcdn.ru media without the optional host grant, publish unavailable immediately and leave native playback intact without issuing a media fetch. The offscreen document relies on the SW capability flag rather than unavailable permissions APIs or persisted refusal metadata. Other direct sources retain their normal CORS path. With EQ enabled and the required access available, fetch a local Blob with omitted credentials, a 15-second deadline and a 32 MiB streaming size limit **before the first play**. Then assign the local source, prepare the graph and start once. This avoids the original implementation's native-start -> source-replacement/rebuffer in the first seconds, and avoids downloading native media and the processing copy concurrently. Preparation can increase startup latency; denied CORS/network/size failures start the native source without EQ. With EQ disabled the native streaming path remains immediate.

Live VK Mix reproduced this boundary: native playback continued from vd544.okcdn.ru while an extension fetch failed and status was unavailable. The manifest declares `https://*.okcdn.ru/*` only as optional access: optional_host_permissions in Chrome and optional_permissions in Firefox to retain support for Firefox 113 (the newer optional-host key starts at 128; [MDN](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/optional_permissions)). Existing required VK access is unchanged. No all-sites access or credentials are added.

The first explicit EQ enable opens a dismissible explanation if access is missing and no refusal is remembered. Only its “Разрешить” button calls permissions.request in a user gesture; install/startup, ordinary playback and reopening settings never request it. The dialog explains the audio server, processing purpose and continuation of music without Mix EQ. “Не сейчас”, closing the explanation or denying the browser prompt persists mixAccessDenied, leaves enabled/gains/presets intact and shows “VK Mix пока без эквалайзера” with “Выдать доступ”. Subsequent enables do not nag; that button reopens the explanation and allows another native request. Grant clears the refusal and sends RETRY_EQUALIZER through the SW, reapplying DSP to the current source without reloading the queue or issuing a playback command. Browser permission-added/removed events refresh the available/denied UI. A previously granted permission remains granted when bypassing EQ; users can revoke it in browser settings.

The optional consent card uses a separate VKUI modal manager. Settings' focus trap is suspended while it is open and restored on close. The existing mandatory VK sign-in permission dialog keeps its original behavior.

Only the current source/settings can adopt a prepared result. Pending pause/resume changes intent without prematurely playing or issuing RELOAD_TRACK; a superseded preparation cannot assign/start the old source even if fetch ignores abort. If the equalizer is first enabled during an already-native track, preparing/replacing that source still restores its current position and can briefly rebuffer. Further bypass/on changes reuse the connected local source. No URLs/media enter persistent storage. Preparation/unavailable feedback is a compact current-track status above the settings group, separated from configuration by a divider. The unavailable text has no trailing period. Waiting/active boilerplate is hidden; the preset selector keeps its accessible label without a visible heading. Converted playback waits for both metadata/position restoration and DSP readiness before resuming. If context preparation rejects, the local-media fallback still resumes at the restored position without EQ.

## First-release discovery and missing-access hint

The update listener compares numeric one-to-four-component extension versions against 3.3.10, padding omitted components with zero. Only UPDATE from a version below that threshold to a version at or above it marks equalizerAnnouncementPending. Skipped minor/major releases qualify; fresh installs, downgrades and updates from 3.3.10 or newer do not. This settings key survives clearStorage, including further updates before first opening. The UI consumes it only when actually presenting the delayed announcement, preventing repetition on later opens. The release workflow owns the actual manifest version bump.

Navigation anchors a non-modal, closable VKUI Popover to Settings. The discovery text points to Sound. A higher-priority missing-access hint requires enabled EQ, actual playing state, unavailable DSP, an HTTPS okcdn.ru/subdomain source and a known missing grant. Source observation includes URL hydration for the same track ID. It explains that the track plays without EQ and directs the user to Sound permissions. Both hints wait 1.5 seconds for navigation/layout to settle, then close after five visible seconds, by their close button, Escape/outside click or opening Settings; they do not steal focus or disable the global Space shortcut (the popover is a non-modal region). Duplicate responsive navigation roots share hint and permission state; hidden anchors hide their popover. Missing-access hints do not repeat on each track within the current UI document; enabling again or granting access resets that episode.

## Stable unavailable state and permission styling

An unavailable current source is not retried when enabled settings change: preset selection, band/Preamp edits and permission-decision metadata must not restart download preparation. This avoids loading/unavailable status churn and repeated denied requests. A new source, explicit bypass/re-enable or RETRY_EQUALIZER can attempt processing again, but ungranted okcdn.ru sources never issue processing fetches. A newly observed grant can retry the current source; already-local media remains usable without another network request. The retry command forwards an optional retry=true on CHANGE_EQUALIZER in both transports; ordinary settings forwarding omits it. The offscreen owner still checks source identity and intent before adopting a result.

Missing Mix access is a warning-colored note with a lock icon, distinct title, server explanation and primary Give access action. This is an optional processing restriction; the EQ switch and native music remain usable. The theme field and its menu are 240 px wide. The Settings shortcut group no longer includes a separate Space explanatory sentence; the shortcut itself is retained. User-facing message/helper copy follows the no-terminal-full-stop rule in AGENTS.md; sentence punctuation, domains, URLs and user content remain intact.

Pending gear hints cancel when the underlying access requirement disappears or Settings is opened during the 1.5-second delay. Announcement state remains pending until presentation or explicit discovery through Settings. Hide/show state is independent from message kind, retaining the same text during closing animation rather than swapping to announcement copy.
